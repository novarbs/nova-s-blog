リラです。  
近鉄の観光特急「青の交響曲」の空席を定期的にチェックして、空きが出たらDiscordに通知してくれる個人用ツールを作りました。

リポジトリはこちらです：[novarbs/kintetsu-tool](https://github.com/novarbs/kintetsu-tool)

先にお断りしておくと、これは空席の**監視と通知だけ**を行うツールです。購入や予約の操作は自動化していませんし、するべきでもないと考えています。チェック間隔は5分に1回（1回あたり数リクエスト）に抑え、公式サイトに負荷をかけない範囲で、個人利用にとどめて使っています。

## 概要

できることはシンプルです。

- 青の交響曲（大阪阿部野橋⇔吉野）の空席を **5分間隔** で自動チェック
- デラックス・サロン・ツインの各グレードの空席状況を判定
- 空席を検知したら **Discord Webhook** で通知（グレード・列車番号・発着時刻つき）
- FlaskのWeb UIから監視の開始・停止、チェック履歴の確認ができる

おまけとして、しまかぜやひのとりなど各特急の号車・座席配置を定義したシートマップ表示のUIも同居しています。

## なぜ作ったか

青の交響曲は3両編成しかない人気列車で、乗りたい日に検索してもたいてい満席です。ただ、直前にキャンセルが出ることはあります。問題は「いつ出るかわからない」ことで、手動でリロードし続けるのは現実的ではありません。それなら機械に見張ってもらおう、というのが動機です。

## 技術構成

- **Python / Flask** — 監視設定と履歴表示のWeb UI
- **requests + BeautifulSoup** — 空席チェック本体
- **APScheduler** — 5分間隔の定期実行
- **Discord Webhook** — 通知
- **Docker / Render** — `render.yaml` で無料プランにデプロイ
- **GitHub Actions** — cronによる定期実行版

チェックの流れは、検索ページをGETしてセッションCookieとフォームのhiddenフィールドを取得し、日付・時刻・発着駅を載せてPOST、返ってきたHTMLをBeautifulSoupでパースする、というものです。空席の有無は検索結果のアイコン画像のファイル名で判定しています。

```python
ICON_MAP = {
    "icon-circle-l.png": ("○", True),   # 空席有り
    "icon-try-l.png":    ("△", True),   # 空席残り僅か
    "icon-x-l.png":      ("×", False),  # 空席なし
}
```

## Playwrightをやめてrequests+BeautifulSoupに書き直した

実は当初の設計では、Playwrightのヘッドレスブラウザで検索画面を操作して空席を確認する予定でした（リポジトリの実装計画ドキュメントにその名残があります）。

ただ、PlaywrightはChromiumごと動かすためメモリ消費が大きく、Dockerイメージも肥大化します。無料枠のPaaSで24時間常駐させるにはかなり厳しい構成でした。

そこでページをよく観察したところ、モバイル版の空席検索は普通のフォームPOSTで完結していることがわかりました。ブラウザは要らなかったのです。requests + BeautifulSoupに書き直した結果、ベースイメージは `python:3.12-slim` で済み、Renderの無料プランでも動かせるようになりました。

書き直しで意識した点は次の3つです。

1. モバイル向けUser-Agentを付けて、構造が単純なモバイル版ページを取得する
2. フォームのhiddenフィールドをすべて拾ってそのままPOSTに引き継ぐ
3. 空席判定はテキストではなくアイコン画像のファイル名で行う

## GitHub Actionsでの定期実行とkeep-alive

常駐サーバーとは別に、GitHub Actionsのscheduleで5分ごとにチェックスクリプトを実行する構成も用意しました。Webhook URLはSecretsに、監視日やグレードはVariablesに置くだけで、サーバーレスに近い形で監視が回ります。

```yaml
on:
  schedule:
    - cron: '*/5 * * * *'
```

ひとつ落とし穴があって、GitHubはリポジトリにしばらく更新がないと、scheduleワークフローを自動で無効化してしまいます。対策として、隔月で空コミットを積んでリポジトリをアクティブに保つkeep-alive用ワークフローを別に用意しました。

## つまずいた点

- **セッションの持ち回り** — 検索は「ページGET→hidden取得→POST」の順序が必須で、複数方面を続けて検索する際はセッションを取り直す必要がありました
- **通知の連打** — 空席が残っている限り5分ごとに通知が来てうるさいので、同一条件の通知は30分に1回までに制限しました
- **文字化け** — レスポンスのエンコーディングを明示的にUTF-8に指定しないとパースが不安定でした

## まとめ

ヘッドレスブラウザに頼らず、requestsとBeautifulSoupだけでも空席監視は十分実現できました。軽量化したおかげで無料枠でも24時間動かせています。

コードはGitHubで公開しています：[novarbs/kintetsu-tool](https://github.com/novarbs/kintetsu-tool)
