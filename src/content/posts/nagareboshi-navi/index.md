こんにちは、リラです。
今回は初めてのネイティブiOSアプリ「流れ星ナビ」を紹介します。スマホを夜空にかざすと、向けた方向の星空をリアルタイムに描画してくれる、天体観測初心者向けの星図アプリです。

(リポジトリは現在非公開です。この記事では設計と実装の考え方を紹介します)

## 概要

「流れ星ナビ」は、2026年のペルセウス座流星群に向けて作ったアプリです。主な機能は次のとおりです。

- スマホを向けた方向の星空をリアルタイム描画（センサー追従の星図モード）
- 星座線と星座の和名、明るい星の固有名（ベガ、アルタイルなど）の表示
- 北斗七星・夏の大三角・カシオペヤのWを専用色でハイライト
- 流星群の輻射点の方向へ、画面外なら矢印と角度差で誘導するガイド
- 暗順応を守る夜間赤色モードなどの観測サポート

恒星データはHYG Databaseから視等級5.0までを抽出して内蔵しており、星図はオフラインで動作します。現時点ではTestFlightでの配信までで、App Storeでの正式公開はまだです。

## なぜ作ったか

2026年のペルセウス座流星群は8月13日11時（JST）が極大で、しかも当日は新月。月明かりゼロという絶好の条件です。「この日までに動くものを出す」という明確な締切があったので、8月2日に要件定義書を書き、その日のうちにTestFlight配信を目指すという突貫スケジュールで開発を始めました。

作る前に既存の星座アプリの競合調査もしました。Star Walk 2やStellarium Mobileなど有名どころを一通り調べた結果、多機能な星座アプリはすでにたくさんあるものの、「日本語・無料・広告なしで、流星群の輻射点まで矢印で誘導してくれるアプリ」は見当たらないことが分かりました。また、既存アプリは多機能ゆえに、初心者には「北斗七星がどれか」すら探しにくいという課題も感じました。そこで「初心者特化・流星群特化」に振り切ることに決めました。北斗七星や夏の大三角の強調表示は、この方針から来ています。

## 技術構成

- 言語/UI: Swift + SwiftUI（星図描画はCanvas）
- センサー: CoreMotion + CoreLocation
- 恒星データ: HYG Database（視等級5.0まで・内蔵）
- 配信: TestFlight

センサーまわりの核はCoreMotionのDeviceMotionです。参照座標系に `xTrueNorthZVertical` を指定すると、磁気コンパスと位置情報を組み合わせて「真北」基準の姿勢行列が取れます。

```swift
motion.startDeviceMotionUpdates(using: .xTrueNorthZVertical, to: motionQueue) { [weak self] dm, _ in
    guard let self, let dm else { return }
    self.lock.lock()
    self._rotationMatrix = dm.attitude.rotationMatrix
    self.lock.unlock()
}
```

星の位置計算は、恒星の赤経・赤緯から、グリニッジ平均恒星時（GMST）→地方恒星時（LST）→観測地ローカル座標（北・東・天頂）へ変換する標準的な手順で実装しています。これとデバイスの姿勢行列を組み合わせて、透視投影で画面に描画します。

## 工夫した点・つまずいた点

一番の山場は座標変換でした。天球側の座標系（赤道座標→ローカルNEU座標）と、CoreMotion側の座標系（x=真北、y=西、z=天頂）で軸の取り方が違うため、符号の入れ替えが必要になります。

さらにつまずいたのが、姿勢行列の「行と列」の解釈です。行列を列ベクトルで読むか行ベクトルで読むかで結果が変わり、間違った読み方をすると方位が90度ズレたり、端末を左右にロールすると南北が反転したりしました。数式上はどちらももっともらしく見えるので、最終的には実機で夜空と見比べて正しい読み方を確定させました。シミュレータではセンサーが動かないので、この検証は実機頼みです。

もうひとつの工夫は精度への割り切りです。磁気コンパスの誤差はどうしても残るため、星座同定に足りる方位±5度程度を目標にしつつ、精度が落ちたときは警告と8の字キャリブレーションの案内を出すUIでカバーしています。

## まとめ

締切が実在する開発は、機能を削る判断が早くなるのが良いところでした。惑星表示や英語対応は最初からv2以降に回し、「初心者が流星群を楽しめる」ことだけに集中できました。

8月13日の夜、このアプリを片手に流れ星を待つのが楽しみです。
